# 完整動作規劃與本機執行

2026-09-23 第二輪改動：Astra 先取得腕部影像與機器人狀態，評估或提出完整動作。本機檢查整段路徑後接續執行，不再每移動幾毫米就停下來等待雲端。

這是現有控制器的程式化動作能力，沒有新增 VLA、訓練馬達政策，亦沒有讓模型直接執行任意程式碼。

## 各動作如何規劃

| 入口 | 開始前的模型工作 | 執行中何時再問模型 |
| --- | --- | --- |
| 獨立揮手／wave 技能 | 本機產生原地或抬高後揮手的完整候選；一次 Astra 選擇整段 | 上抬與兩輪揮腕之間不再呼叫；用實測幅度、回程與控制器條件核對完成 |
| 1–30 mm 空手平移 | 本機 IK 產生完整關節插補路徑；一次 Astra 評估 | 段內不呼叫；以實測進展核對方向與距離 |
| 抓取 | 一次提出接近、輕合、試提的完整有條件程序 | 合爪前核對內夾面與物件；試提後核對是否真的抓住 |
| 搬放／堆疊 | 一次提出抓取、試提、搬運、降低、放開的完整程序 | 保留抓取核對，再檢查目的地支撐與最後放置結果 |

文字搜尋仍可能先經 Jev／Astra 分類，再由 Astra 組合技能；這張表描述各動作的視覺規劃，不代表複合使用者指令只有一次模型呼叫。Jev 沒有接管馬達，也不會提高 Astra 或 VLA 本身的推論速度。

## 本機執行契約

`wave_program.py` 擁有固定揮手候選與單次選擇 schema；`translation_program.py` 負責完整空手平移；`object_program.py` 負責有條件的物件程序；`motion_program.py` 驗證並執行共用身體軌跡。正式 API 和技能執行器已接到這些入口。

- 本機沿用約 25 Hz 的馬達插補與回饋。目標、實體保持補償、允許誤差與相機裝置身分在規劃時固定；不得把尚未到達的端點偷偷改成新的計畫終點。
- 身體動作不得帶入夾爪命令。夾爪開合與可能接觸仍由低出力控制器管理；低輸出、故障恢復與停止紀錄不因完整計畫而省略。
- 每個通用身體段至多 180 ticks／軸、模型手端路徑至多 80 mm。完整 robot mesh 對桌面做路徑與追蹤誤差檢查，實際運動保留更窄的量測條件。桌面檢查不等於外部物件或持有物體碰撞模型。
- 揮手完整計畫的肘部上抬仍限起始姿勢起算向上 60 mm、側向 15 mm、旋轉 15°，保持其他軸，並預留追蹤誤差；後續轉腕以原始 wrist-roll 中心固定。合格候選不一定用滿這些上限。
- 揮手（含一次換視角）共用 45 秒執行期限；單段平移仍為 30 秒。物件程序最多八個語意步驟、累計 30 秒實際操作；雲端規劃、接觸與結果核對等待不占該物理時間預算。放開等夾爪步驟另外預留其有限驅動時間。
- 場景在雲端判斷期間變動、相機更換、保持目標改變、取消或實際姿勢超出已確認範圍時，停止後續派送。動作段中的馬達及相機檢查不會重新問 Astra。

2026-09-24 補充：固定關節接近行程邊界時，幾何檢查與實際允許範圍分開表示。
例如肘部實測 3042、原保持目標 3040、馬達上限 3045，原本的對稱 ±4
假設會把幾何範圍算到 3046，導致連單獨轉腕也沒有候選。現在仍使用完整
`geometry_bounds=[3038,3046]` 檢查 robot mesh 與桌面；實際回讀和保持目標的
`measured_bounds`／`raw_bounds` 則與馬達及 URDF 行程取交集，最多只允許到
3045。這個肘部保持原目標，執行器不重寫它；每次回讀仍檢查裁切後的界線。
模型或校正變動使界線不同時，既有動作契約必須重新規劃。這項調整沒有縮小
幾何誤差範圍，也沒有增加任何運動軸的行程餘量。

這項修正只讓其他關節能在肘部固定時移動。若要讓該肘部自己從邊界向內
退開，通用動作仍要求起點具備原有追蹤範圍及額外 12 ticks 餘量，因此目前
不會執行。未來需要獨立、明確核准的「向內恢復行程」動作，包含不向外的
命令、完整幾何範圍、實測停止條件，以及腕部影像對整條外物路徑的確認。

## 持續觀察目前做到哪裡

2026-09-26：`prepare_joint_segment` 可明確設定 1–12 ticks 的固定身體軸容許值，預設仍為 4。空手補看候選選用 12 ticks（約 1.05°），同時納入實測區間、完整幾何、整次觀察位移餘量與提供 Astra 的路徑契約。每段沿用固定起點與原保持目標，不重送固定軸命令，也不逐次重新置中漂移；超出該段範圍或實際行程仍停止。一般物件操作、夾爪與起步條件不因這個觀察設定一起放寬。

運動期間檢查的是腕部相機持續更新、裝置不變、馬達回讀與控制器界線。**目前沒有背景 VLM 持續辨識新障礙，也沒有在運動中由 Astra 隨時改寫軌跡的功能。** 開始前的整段外物判斷與接觸／支撐節點的新影像核對是分開的機制，不能把前者視為未來環境永遠不變的保證。

產品只使用 Follower 加腕部相機。D435 仍由獨立工程工具錄影或取得深度，供開發者從旁核對是否真的抬手、揮動或碰觸；其影像、座標與摘要不進正式 Astra／Jev／控制器輸入。

## 證據與尚未完成的部分

離線測試使用真實 CAD、假串列馬達和結構化模型回覆，涵蓋整段核准、相機與停止中斷、名義端點／實際誤差、接觸與支撐條件，以及沒有成功證據不能回報完成。它能驗證軟體是否照契約執行，不能驗證視覺判斷的真實性或單腕相機的抓取精度。

本輪尚未完成新版自主揮手、抓取、搬放或堆疊的實機成功驗證。已有的人工接手揮手與較長單肘弧線是舊輪次的獨立證據；不要把它們合併成新程序已完成的紀錄。歷史耗時和這輪進度見 [LATENCY.md](LATENCY.md)。
