# 2026-09-23：局部進展、技能指令與 Jev

## 這次改動

- 空手短步可接受停穩且有意義的部分進展；要求 3 mm 而實際約 1.5 mm，不會只因沒有精確到位就失敗。停穩、方向、姿態與路徑條件仍各自檢查，後續必須重新觀察。
- 局部移動、揮手、接觸與抓取驗證的視覺門檻分別為 0.7、0.8、0.9、0.9。
- 新增 `POST /api/command`、`GET /api/skills` 與網頁「執行動作」。Astra 拆解有限步驟，本機逐步執行；失敗保留已取得的進展，不執行後續步驟。
- Jev 只排序當次已經通過檢查的退讓候選。不能提供新的馬達指令、解除阻擋或取代腕部視覺。
- 修正動作途中失敗卻顯示「尚未執行」的回報；第一個未完成步驟改為「未確認完成」。相機一開始不可用時，在讀取手臂姿勢前回報，不因此進入停止保持流程。

## 真實 Jev 連線

官方 `https://api.typesafe.ai/v1/systemone` 接受一次合成的語意狀態與有限選項，回傳 `jev-1.13.0`，選擇 `raise`，confidence 0.86、該選項 probability 0.91。這次端到端等待約 **703.334 ms**，使用 491 個輸入 token、41 個輸出 token。

這是實際雲端 API 測試，沒有傳入相機圖片、操作硬體或證明持續即時頻率。去除機密的回應保留於 `.runtime/jev-live-smoke.json`，未納入 Git。金鑰只在 Git 忽略的本機設定檔；本機診斷僅顯示是否可用，Codex 子程序也不接收這把金鑰。
