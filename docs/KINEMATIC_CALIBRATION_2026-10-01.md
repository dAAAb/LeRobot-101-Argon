# 運動學校準與 Astra 評估筆記（2026-10-01）

Claude Code（Opus 5.5）在 M4 Max 機上完成。手臂：follower `5B415309611`（EEPROM 與 LeRobot-101-OS 9/2 校準檔一致，全程未改寫）；腕部相機：`icspring camera`。分支 `claude/kinematic-calibration`，以 `codex/spatial-v2`（`41df50d`）為基底。

## 〇、2026-10-02 更新：第三個位置（Neo）

在 Neo 上補拍左前方位置，模型改用三個位置擬合。**現行模型檔：`config/calibration/kinematic-model-20261002.json`**（`kcal_model.load_model()` 的預設值已改指向它；10-01 的兩位置模型檔保留供比較）。

- **位置 3**：手臂左前方，棋盤中心 (361, 225) mm，距底座約 42 cm（D435 畫面右側）。搜尋第一個目標就找到，棋盤相對模型桌面傾斜 0.24°、高度差 −0.9 mm。拍了 14 個姿勢，共 16 張；可用 12 張（3 張棋盤上緣出框，1 張 10×6 歧義被排除）。全程沒有中止，路徑最小淨空 52.7 mm。紀錄：`search-20261002-150518`、`session-20261002-150606`。
- **留一個位置交叉驗證**（`kcal_loo.py`；凍結其他兩個位置擬合出的模型，只估棋盤擺放，用保留視角算角點 3D 誤差）：

| 擬合 → 預測 | 中位 | 最大 |
|---|---|---|
| P1+P2 → P3（即 10-01 的模型） | 6.7 mm | 10.0 mm |
| P1+P3 → P2 | 2.0 mm | 4.4 mm |
| P2+P3 → P1 | 4.3 mm | 7.6 mm |
| 三個位置一起擬合（保留視角） | 2.8 mm | 4.5 mm |

- **修正 10-01 的結論**：兩位置模型的 2.6／4.3 mm 只在擬合過的區域成立；到了沒見過的左前方是 6.7／10 mm。三位置模型的零位為肩升 −1.88°、肘 +2.80°、腕俯仰 −1.37°，桌面高度 −2.9 mm，傾斜仍為 1.06°。肩升比 10-01 少了約 1°，超過當時標示的 ±0.26°。
- **零位的標準差被低估**：三組交叉驗證各自算出的零位彼此相差約 1–1.7°（肩升 −1.3 至 −2.9°、肘 +1.7 至 +3.4°、腕 −0.4 至 −2.1°），是報告 std（約 0.15°）的 5–10 倍。代表還有未建模的誤差（回差、重力下垂、連桿長度）在和零位互換。個別零位值不要當成物理真值；在三個位置涵蓋的範圍內，端點誤差是可信的。
- **Neo 上的坑**：OpenCV 的 `findChessboardCornersSB` 在工作執行緒裡建 OpenCL kernel，在 Apple OpenCL 驅動直接 segfault。`cv2.ocl.setUseOpenCL(False)` 只對呼叫它的執行緒有效。現在 `kcal_common.py` 在 import cv2 前設 `OPENCV_OPENCL_RUNTIME=disabled`。第一次搜尋另外出現過一次「no fresh camera frame」中止，原因未確認；之後兩次都正常。
- **另一個坑**：Astra 後端 `/api/status` 的 `robot.position` 是上次 `read()` 的快取，不是即時值。用它估姿勢會錯；要直接讀馬達。

## 〇之二、2026-10-05 實機驗收：爪尖停在角點上方 10 mm（Neo）

工具：`kcal_hover.py`。先用新拍的腕部影像定位棋盤（PnP 0.23 px，角點和模型桌面差 0.13 mm），目標是最靠近手臂的內角點 (8, 5)，基座座標 (306, 147) mm。TCP 定義為兩個 CAD 爪尖最低區域的中點（gripper_link 座標 (−1.2, −0.2, −104.6) mm），用腕轉讓兩爪尖等高。下降路徑為 80→40→25→15→10 mm。

| 紀錄 | 結果 |
|---|---|
| `hover-20261005-113334` | **安全底線中止**。每段實測間隙都比指令低 10–12 mm（80→66.5、40→28.2、25→13.5、15→4.6 mm），水平偏 8–9 mm。原因：**伸展姿勢下肘關節穩定下垂 31–36 ticks**（實測比指令低），其他關節 3–9 ticks。觸發 5 mm 底線後保持姿勢並退回。 |
| `hover-20261005-113511` | **完成**。加入靜差前饋（每段停穩後把「指令−實測」加到下一段）後，實測間隙為 40→38.7、25→24.2、15→17.0、**10→9.68 mm**，水平偏差 **0.65 mm**，路徑最低網格 8.9 mm，沒有碰觸。腕部影像中，模型預測的角點像素和實際角點目視重合（這個距離 1 px ≈ 0.13 mm）。D435 640×480 看得到手臂停在棋盤上方，但分辨不出 1 cm。 |

**更正（10-05 稍後）**：`kcal_hover.py` 的 TCP 假設 CAD 活動爪角度 = (raw − 2047)。但 Astra 已註明「馬達行程校準沒有量到夾爪的 CAD 零點」。依夾爪 profile，raw 2033 實際開口約 64 mm，所以當時算的「活動爪尖」位置是錯的。

- **垂直 9.68 mm**：仍可近似視為**固定爪尖**的高度（該 TCP 點和固定爪尖等高，差 < 1 mm）。
- **水平 0.65 mm**：量的是 gripper_link 座標中「固定爪尖往內約 9.6 mm」的固定點，不是兩爪中點。
- **路徑最低網格**：真正的活動爪尖高約 9 mm，所以當時算的值不準；但路徑淨空留得很寬。
- **之後的程式**：`server/kinematic_grasp.py` 改用夾爪 profile 實測的夾墊位置，不再用 CAD 夾爪角度。

結論與限制：

- 在已知舵機靜差的前提下，模型加上本機 IK 可以把爪尖放到角點上方 ±1 mm（以實測關節角計算）。**10 mm 的垂直間隙還沒有獨立的物理量測**：腕部 PnP 被爪子擋住，D435 解析度不足。下次可以用尺或塞規確認。
- **接回 Astra 時必須處理重力靜差**：不補償的話，伸展姿勢會低 1 cm 以上。可選前饋（本工具的做法）、閉迴路，或提高肩肘 P 值（需同意）。「誤差預算」裡的 3–11 ticks 只適用於校準姿勢。

## 一、結論

- Astra 至今**沒有任何一次成功抓取**。主因不是馬達校準錯，而是：從未擬合關節零位、早期讓 LLM 直接給馬達刻度、雲端模型放在控制迴圈、容差比舵機物理極限還嚴，以及 v2 的「校準域」和最壞情況誤差疊加讓手臂幾乎不能動。
- 這次用**兩個棋盤位置**做了運動學校準（軟體關節零位＋手眼＋共用桌面平面），在沒參與擬合的視角上，棋盤角點誤差**中位 2.6 mm、最大 4.3 mm**。同樣條件下 Astra v2 在沒校過的位置是中位 8.6–9.6 mm、最大 12–16 mm。
- 對白罐（直徑 35 mm、夾爪開口約 64 mm、每邊約 14 mm 餘裕）而言，2–4 mm 已足夠。下一步是把模型接回 Astra，改用桌面射線定位與本機規劃去抓（見〈八、待辦〉）。

## 三、校準方法

- **量測**：腕部相機看固定在桌面的 A4 棋盤（20 mm、9×6 內角點、左上黑格），手臂在多個姿勢停穩後取像，記錄停穩期間的實測關節角（取像前後各讀三次，期間零晃動）。
- **模型**：沿用 Astra URDF FK，角度 = `(raw + offset_ticks − 2047)·2π/4096`。
  - 未知數：肩升／肘／腕俯仰的**軟體**零位偏移、手眼 `gripper_link → wrist_camera_optical`、一個所有棋盤共用的桌面平面（高度＋兩軸傾斜）、每個棋盤在桌面上的 (x, y, yaw)。
  - 肩轉零位會被棋盤 yaw 吸收、腕轉零位會被手眼吸收，數學上不可觀測，固定為 0。
  - 內參只用訓練視角，採 k1、k2、k3、p1、p2，並檢查畸變在整個畫面範圍內單調。
- **驗證**：每個位置約 1/3 視角保留不參與擬合，另做「留一個位置」交叉驗證。
- **安全**：
  - 只寫五個身體關節的 Goal_Position，用 sync write，封包位元組已離線驗證。
  - min-jerk 插值 50 Hz，峰值 100 ticks/s（約 9°/s）。
  - 以下任一情況立即保持姿勢並停止：追蹤誤差 >120 ticks、負載 >75% 持續 0.3 s、Status≠0、扭力被關、溫度 >55°C。
  - 路徑用 Astra mesh 檢查桌面淨空 ≥ 50 mm，或不低於起點的淨空。
  - 夾爪、扭力、EEPROM、增益一律不寫。
- **實機紀錄**（全程無中止、無碰觸）：

| 紀錄 | 內容 |
|---|---|
| `session-20261001-173351-test` | 腕轉 +30 ticks 往返測試 |
| `session-20261001-173458` | 位置 1（手臂右前方，距底座約 47 cm），24 姿勢，26/26 偵測 |
| `search-20261001-184028` | 位置 2 的搜尋，第 2 個目標點找到 |
| `session-20261001-184230` | 位置 2（手臂正前方，距底座約 33 cm），14 姿勢，13 張可用 |

## 五、重要發現與坑

- **一個棋盤位置不夠**。只用位置 1 時，肩升零位會和棋盤傾斜互換：棋盤姿態自由時算出 −5.0°、強制桌面水平時算出 −2.2°；兩個單一位置模型給出的零位彼此差到 ±2°。至少需要兩個位置，第三個位置能進一步釘死。
- **桌面相對底座傾斜約 1°**。兩個棋盤各自獨立算出 0.88°／0.91°，方向一致。
- **鏡頭需要 k3**。保留視角的單張 PnP 最大誤差從 2.0 降到 0.7 px。有理式模型在畫面角落不單調（會折疊），Astra v2 的這個顧慮是對的。
- **9×6 視窗錯位**。斜角拍攝時，OpenCV 可能多抓一排假角點，同一張畫面也偵測得到 10×6。現在由 `pattern_ambiguous()` 自動排除，求解器另有離群剔除。
- **角點順序 180° 歧義**。斜角時顏色判斷可能失準，改用模型預測距離決定：兩個候選相差約 250 px，預測誤差只有 70–150 px。
- **棋盤離底座太近時很難拍**。棋盤離底座約 35 cm 以內時，夾爪會擋住畫面下半部，可行姿勢很少。位置 2 的規劃器邊距因此放寬。
- **Astra 留下的停放姿勢**，夾爪離桌只有約 46 mm，所以路徑規則改為「≥ 50 mm 或不低於起點」。
- **舵機**：P/D/I = 16/32/0，靜止穩態誤差 3–11 ticks。min-jerk 100 ticks/s 時，追蹤誤差峰值 12–42 ticks。
- **串列通訊**：單次往返 0.33 ms，sync read 0.9 ms，不是瓶頸。
- **ffmpeg**：avfoundation 會回報 1000k tbr，輸出必須加 `fps` 濾鏡，否則會無限複製畫面。icspring 用 `nv12`。D435 的 AVFoundation 介面可用 `640x480`、`uyvy422` 取得紅外線畫面（含投射光點）。
- **macOS 相機 uniqueID 會隨 USB 埠改變**（`0x100…`／`0x121…`／`0x2110…`），Astra 綁死 ID 會開不了相機；本工具改用裝置名稱。
- **Xcode license**：M4 Max 機沒同意，`swiftc` 失敗，Astra 的 `start.sh` 起不來。
- **自動模式**：Claude Code 的安全分類器曾擋下一次搜尋移動，使用者明確同意後才放行。

## 六、工具與指令

所有指令都在 repo 根目錄、用 Astra 的 Python 環境（`requirements.txt`）執行。

執行前提：
- **先停掉 Astra 服務**，因為串列埠是獨占的。
- 需要 `ffmpeg`（Neo 若沒有：`brew install ffmpeg`）。
- 手臂扭力需已開啟，本工具不會開扭力。

| 指令 | 會移動手臂？ | 用途 |
|---|---|---|
| `python scripts/kinematic_cal/kcal_model.py [session…]` | 否 | 從 `config/calibration/kinematic-sessions/` 重算模型，輸出到 `.runtime/kinematic-cal/kinematic-model.json` |
| `python scripts/kinematic_cal/kcal_hover.py --plan-only` | 否（只拍照） | 驗收：定位棋盤並規劃讓爪尖停在角點上方（預設 10 mm）；`kcal_hover.py` 執行（**會移動手臂**，低淨空需使用者同意） |
| `python scripts/kinematic_cal/kcal_loo.py` | 否 | 留一個位置交叉驗證（對沒見過的區域的真實誤差） |
| `python scripts/kinematic_cal/kcal_variants.py` | 否 | 比較誤差模型（水平／自由／傾斜桌面、柔度、連桿長度） |
| `python scripts/kinematic_cal/kcal_search.py --target X Y [--target X Y …]` | **是** | 依目標點（基座座標，公尺）找棋盤，找到後停在該姿勢並寫出 `placement.json` |
| `python scripts/kinematic_cal/kcal_plan2.py` | 否（只讀） | 依 `placement.json` 規劃視角，輸出 `plan.json` 與預覽 `plan.jpg` |
| `python scripts/kinematic_cal/kcal_run.py --dry-run` | 否 | 驗證計畫 |
| `python scripts/kinematic_cal/kcal_run.py --test` | **是** | 腕轉 +30 ticks 往返測試 |
| `python scripts/kinematic_cal/kcal_run.py` | **是** | 執行整個計畫並錄影 |

- **停止方式**：`touch .runtime/kinematic-cal/STOP`、Ctrl-C，或直接 kill。馬達會停在最後一個目標附近（每步只有 20 ms）。
- **新增位置後**：把該 session 的 `views.jsonl`、`plan.json`、`summary.json` 複製到 `config/calibration/kinematic-sessions/`，再重跑 `kcal_model.py`。
- `kcal_plan.py`、`kcal_solve.py` 是第一批（以 Astra v2 為先驗）的歷史腳本，保留供重現用。
