# 實驗抓取 prototype

目前已實作腕部影像引導的逐步抓取流程，`config/robot.json` 的 `experimental_pick_enabled` 已設為 `true`。這是可開始實機嘗試的入口，**尚未驗證成功抓取**。

本輪實際做到：張開夾爪，以及數次向右、向前、後退的局部移動，並記錄實際關節位置。修正位置基準後，最後一輪由 Astra 連續完成右移與後退，再因白盒仍遮擋圓筒的夾指通道而停止。尚未確認物件接觸、抓住或抬離桌面成功。程式中的合爪、抬起檢查及持有流程已存在，不能因此宣稱實機已完成。

同一批腕部照片的離線交叉檢查也未找到清楚的夾指通道：六次右移的模型行程約 12 mm，圓筒可見寬度只增加 2–5 px，盒邊與筒身間沒有可辨識的背景縫。相機模型的不確定性仍太大，不能把這項結果換算成兩物件之間的精確毫米間隙。

## 使用方式

1. 搜尋眼前物件。適合觸碰的候選物件會有「抓起來 · 實驗」；旗標關閉或物件不適合時，按鈕不會開放。相機點選目前先做辨識，不會直接抓取。
2. 按下抓取後，查看「對準／輕合／確認」與即時訊息。Astra 每一步重新判斷腕部影像，本機控制器執行一小步，再讀回關節與取像。
3. 若失敗或取消後仍處於 `approaching`，且控制器允許繼續，可再次按物件的「試著抓起來 · 實驗」。這是使用者明確發起的新嘗試，以該物件名稱重新取像，不受前一次搜尋結果到期影響，也不會自動重送可能已受理的 POST。

完成工作不等於抓取成功。只有回傳 `grasp_confirmed: true` 才顯示「已拿起物件」；結果會附上抓取後的腕部影像。失聯、失敗、停止或 `holding_unverified` 都不會被畫成成功。

搜尋結果會保留目前的觀察。若畫面顯示正在保持或尚未確認持有，請先處理目前物件；放置、放旁邊及堆疊的產品操作仍未完成。「好手氣」目前仍是觀察或揮手。

## 每一步如何執行

- 生產輸入只有指定的腕部相機與馬達回饋。D435 旁觀相機及已知圓筒尺寸不提供給抓取規劃；沒有使用物件直徑或高度推算接近距離。
- Astra 提出受限的方向／動作，不提供任意馬達指令。每次局部平移最多 5 mm；若原提案不符合局部 IK、桌面模型或關節限制，只沿同一方向縮小這一步，執行後重新觀察，不一次走完剩餘距離。
- 使用馬達既有校準與 URDF。每一步從新停穩的實際編碼器位置重新建立邏輯目標，同時保留已確認的實體保持目標與補償關係；不把前一步殘留的邏輯誤差當成新目標，也不為重新對齊帳目而重送保持指令。沒有改寫 EEPROM 或校準偏移。
- 移動前後核對影像與姿勢，逐次檢查實測路徑、目標、溫度及停止訊號。末端接受需連續三筆符合局部位置／方向與實際進度條件；修正及紀錄共用三秒預算。

紀錄中的毫米位移是「實際編碼器＋機械模型」的估計，不是外部量測精度。模型工具點仍是固定指墊，並非已校準的雙爪中心；桌面模型檢查也不能證明所有眼前障礙物都已建模。全域立體校準的不確定性並未因此消失。

## 合爪、持有與停止

可能合爪接觸前，控制器先將 `contact_possible` 寫入可持久化的紀錄，夾爪 RAM PWM 上限使用 100（原值 500）。短距離合爪遇到持續停滯與回饋變化，可回報 `obstruction_candidate`；它不是接觸力或成功抓握的證據，也不是空夾爪基線已驗證過的接觸靈敏度。

程式接著安排小幅抬起檢查，讓 Astra 比較是否為同一物件、位於兩爪之間、離開桌面並跟隨夾爪。這段完整實機成功仍待驗證。

| 狀態 | 意義 |
| --- | --- |
| `approaching` | 正在對準，尚未授權這次物件接觸；可在控制器允許時明確重試 |
| `holding` | 本次視覺驗證回報成功，保留低輸出持有；不代表已完成放置 |
| `holding_unverified` | 可能有物件，但尚未確認抓取成功；保留低輸出與接觸紀錄 |
| 停止／pending | 後續操作受阻擋，需確認當前狀態；不能推論已抓住或已放下 |

`holding_unverified` 不會因工作結束而自動恢復 PWM 500。明確停止會在硬體狀態允許時移除剩餘閉合需求並保留低輸出；通訊或馬達異常不會以再次寫入夾爪來盲目重試。停止後仍可能需要人工確認保持狀態。

## 工程釋放與設定

目前只有明確的工程釋放流程（`/api/grasp-release`），不是一般使用者的「放回去」功能。工程操作者須先以新的腕部影像確認物件已有支撐或夾爪空置；流程在低上限下張開，量測開口與靜止狀態，再取得新的腕部空爪證據，才清除接觸紀錄並恢復原上限。普通 `finish`、`recover`、重啟或「恢復」按鈕都不能跳過可能持有物件的釋放要求。

旗標設為 `false` 並重啟控制器可關閉新的實驗抓取。`/api/object-action`、`/api/actions` 與 `/api/grasp-attempt` 在受理時都檢查目前載入的旗標，不能沿用舊搜尋結果中的可用標記繞過設定。關閉入口不會自動釋放既有物件。

程式分工：`server/grasp.py` 管理逐步觀察／動作與結果，`server/local_cartesian.py` 提出同方向局部步驟，`server/robot.py` 執行讀回控制，`server/gripper_power.py` 保留持有／釋放的輸出與恢復紀錄。實際提案、影像及回饋留在 `.runtime/grasp-steps.jsonl` 與 `.runtime/`，不納入 Git。
