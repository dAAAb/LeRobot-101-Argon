# D435 作為開發者的旁觀眼睛

2026-09-23 白天，使用者已開燈並授權實機測試。本工具的用途是「執行 → 從另一個角度核對 → 找原因 → 修改 → 再測」，不只是保存檔案。正式產品仍只需要 Follower 與腕部相機。

## 兩條不同的資料路徑

- 正式操作：使用者搜尋／點選推薦卡 → Astra 規劃 → 腕部影像與馬達回饋 → 本機控制 → 新腕部影像檢查。
- 工程驗證：獨立 D435 擷取 → 有時間戳的錄影 → 開發者視覺核對與程式診斷 → 修改程式與回歸測試 → 再從正式入口實測。

旁觀影像可以讓開發者發現動作沒發生、方向不對或物件被碰動；不能將它直接寫成正式控制器的「已淨空」「已抓住」判定。影像、深度、座標及其文字摘要都不送到正式 Astra／Jev。測試不能靠旁觀相機解除某次動作的條件，也不能把已知圓筒尺寸填入正式定位。

## 本機可用的擷取方式

`ObserverCapture.swift` 用完整裝置名稱及 ID 選擇 RealSense，不使用容易變動的 OpenCV 相機編號。它不讀馬達，不呼叫正式 API。2026-09-23 已開啟的介面為 `Intel(R) RealSense(TM) Depth Camera 435i Depth`，最初取得的是 **640×480 灰階紅外線 UVC 畫面**，可見投影散點。它不是 RGB，也不是已解碼的公尺深度；不能用 JPEG 的像素值當距離。

```bash
mkdir -p .runtime
swiftc scripts/ObserverCapture.swift -o .runtime/observer-capture
.runtime/observer-capture 'EXACT_REALSENSE_NAME' 'EXACT_DEVICE_ID' .runtime/engineer-observer-live.jpg
```

名稱與 ID 必須以該台電腦實際列出的裝置為準。正式腕部攝影機不會被此工具選中。

同日已進一步取得原生 **1280×720**，設定幀率約 6 fps，等比例縮為 960×540 JPEG。6.000006 fps 來自裝置設定的 frame duration，不是實際到幀速率統計；錄影仍使用每張影格的接收時間。可在命令尾端加 `1280 720 6`。macOS 在 `startRunning()` 時會把此 UVC 節點切回預設模式，工具因此在啟動後重新設定已選格式，再核對裝置模式和實際送出的影格尺寸；最多等三秒，不符就退出，不放大或默默換模式。720p 增加了左右可見範圍，**沒有補回超出上緣的高舉夾爪**，這是目前擺放視角的實際限制。

另一個程序記錄這個 JPEG 串流：

```bash
../LeRobot-101-OS/.venv/bin/python scripts/observer_record.py \
  --latest .runtime/engineer-observer-live.jpg \
  --output .runtime/engineering-observer/new-session \
  --seconds 900 --fps 5 --encode-video
```

以 Ctrl-C 提前結束會完成索引及影片輸出。每次使用新的資料夾；最多錄 30 分鐘、每秒 10 張，沒有背景無期限動作或模型迴圈。`--encode-video` 需要可選的 `imageio-ffmpeg`，本機已驗證可輸出 H.264 MP4；不加此選項仍會保存原始 JPEG 和時間索引。

輸出包含：

- `frames.jsonl`：主機到達時間、單調時間、原始檔案修改時間、SHA-256 與影像尺寸。只接收一秒內的新影格，舊快取不冒充即時影像。
- 原始 `frame-*.jpg`、`video.ffconcat`，以及選用的 `observer.mp4`。影片使用實際採樣間隔，不把遺漏影格當等間隔連續動作。
- `session.json`：固定 `source=engineering_observer`、`production_eligible=false`、`physical_success_verified=false`。錄完影片本身不能證明成功。

所有資料保留在忽略的 `.runtime/`，不推到 GitHub。時間戳是主機檔案到達時間，不宣稱相機曝光與馬達精確同步。SDK 的可選深度工具另外記於 [空間狀態文件](WORLD_STATE_GRAPH.md)。

## 如何判斷一輪結果

先保存正式工作的建立與最終回應，再依工作事件時間選取動作前、途中與完成後的旁觀影格。將可見動作與馬達實測、技能收據交叉核對。若畫面裁掉夾爪、被遮住或動作小到看不清楚，就記為外部視覺證據不足；不能從肩肘在動推定完整揮手或成功抓取。

任何修正先以相關回歸測試檢查，再在無進行中動作／夾爪交易時重新載入服務。重新實測仍由正式入口取得新的腕部判斷。一次失敗和修改後的結果分開保存，不用新結果覆蓋失敗證據。

## 通訊與離線驗證

一般馬達讀取遇到無伺服錯誤的逾時／損壞回覆時，最多三次唯讀嘗試；重試前在同一串列鎖內短等並清除已到達的 RX 資料。寫入不重送，馬達保護錯誤不重試。接觸遙測仍為整組失敗即丟棄，避免跨故障拼接讀值；失敗時保留夾爪交易待處理狀態。

空手單肘動作另可在第四次修正後持續唯讀觀察，最多到該次寫入後 0.5 秒；不增加第五次無進展寫入，亦不延長原本 3 秒總期限。模擬的延遲回應可完成，真正停滯仍中止；這項差異未在上述實機姿勢中解決問題。

揮手前的場景更新也涵蓋 `move` 最後兩次取像，但僅限明確標記為尚未派送動作的 `PreMotionSceneChangedError`。新影格需重新建立候選並取得新判斷，與較早的比較共用整次最多兩次更新額度；不重設起點或已完成步數，不重試動作後失敗，也不忽略姿勢、相機世代、停止與取消檢查。

本輪已通過 Python 全套 754 項測試、前端 52 項測試、TypeScript、lint 與 build，含 recorder 起始時間修正的 4 項測試。其中 12 項是新加入的串列失敗注入測試。離線通過不能代替實際揮手成功。
