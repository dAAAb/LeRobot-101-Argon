# Spatial v2：第一階段實作與回退

2026-09-29。對應 [改版規劃](SPATIAL_V2_PLAN.md) 的 P0–P1、P2 最小幾何與 P3 單物件路徑接線。**腕部相機校準已在取樣範圍通過並啟用；兩側夾墊與完整工作範圍仍待實測，尚未完成新版實機抓取。**

當日下午白罐抓取的後續追查、新的 6 個實拍視角、相機誤差診斷、IK 與串口修復，見 [最新實機紀錄](GRASP_VALIDATION_2026-09-29.md)。新工作範圍尚未套用，勿將下述原 16 張的誤差沿用到所有姿勢。

## 本輪改變

- `spatial_contract.py`：不可變的腕部影像／馬達座標封包；公尺、座標方向、原始尺寸、裁切縮放、Brown 畸變、相機世代、校準版本皆明確。使用停穩讀值跨取像的時間區間，沒有宣稱 JPEG 到達時間等於曝光時間。
- `board_calibration.py`、`calibration_store.py`：固定棋盤、多方向手臂姿勢求內參與相機安裝位置；訓練與保留視角分開，求解失敗也保存原始照片。驗證的是**取樣工作空間內的相機＋FK 組合**，不宣稱已單獨辨識每個關節零位。範圍與實測誤差進入版本指紋；超出取樣關節範圍不能當已校準資料。
- `object_geometry.py`：分開可見表面、完整尺寸與抓取中心。以前的良好估距不會因較差的新視角而完全消失，但舊結果只能供診斷，不能冒充當前可執行座標。圓筒擬合需足夠弧面與高度支援；不能把前表面當圓心。
- `task_space_plan.py`：SO101 五自由度求位置＋接近方向，軸向旋轉保留自由；使用兩夾墊中央的 TCP 與實測開口，不再只使用固定指尖座標。離線路徑點合併成已檢查的連續動作段；不逐點詢問 Astra。
- `spatial_object_program.py`：Astra 決定目標、形狀、觀察需求及外物淨空；本機決定數值路徑。合爪後按新開口重新規劃一次試提，再做新路徑判斷。馬達阻擋依然只表示可能接觸，拿起成功需要新影像核對。
- `/engineering/calibration`：下載棋盤、保存不同姿勢照片、求解、明確套用通過的候選、切回舊版。補拍後明示上次計算用了幾張、目前有幾張，舊結果不能套用；按鈕與送出請求前都檢查。套用與模式切換要求空閒、停止、無未完成夾爪持物紀錄，不發動馬達。

Boxer 的概念用於分離幾何與語意，不安裝大型模型作為本階段前置條件。ARKit／外部 iPhone 回傳仍在 backlog。D435 未接入任何上述正式校準、估距或規劃。

## 校準操作

1. 開啟 `http://localhost:3100/engineering/calibration`，下載棋盤。A4 橫向，100%／實際大小；不要符合頁面。列印後核對線長 100 mm。每格 20 mm，共 10×7 格、9×6 內角點，左上黑格。
2. 貼平於硬板，在明亮桌面固定；同一輪照片中不能移動紙張。這是暫時的設定工具，正式使用不需要棋盤或 D435。
3. 建立一輪校準。相同姿勢連拍不算不同視角；至少 12 個分散姿勢，需多個旋轉方向、畫面覆蓋與足夠棋盤大小。頁面的「拍攝」只等待手臂停穩並取像，**不會自行移動或解除停止**。開發時另外安排已檢查的空手視角，並以旁觀工具驗證動作。
4. 求解保存報告及候選；最少保留 3 個獨立姿勢驗證，不自動套用。移動棋盤、相機重連或影像尺寸變更需另開一輪。換相機支架或改手臂模型需重新校準／變更 mount revision。
5. 機械臂停止且沒有持物時，可套用通過的候選。驗證誤差是所測視角的經驗誤差，不是全工作空間的保證；仍需另驗兩側夾墊、開口曲線與 TCP。相機校準成功不會自動宣告抓取已就緒。

照片與報告：`.runtime/calibration-sessions/<session>/`。每次求解有獨立 `solves/<solve>/report.json` 與候選設定，原照片複製保存並檢查 SHA256。這些本機資料不進 Git。明確套用時，已驗證的 profile 與報告原樣保存到可納入 Git 的 `config/calibration/<session>-<solve>-{profile,report}.json`，確認兩份檔案完整後才切換設定；同版本不同內容不能覆寫，原始照片與密鑰不會複製。

### 工程取景

`POST /api/engineering/calibration/views/plan` 接受 `session_id`，只取得腕部畫面並計算退後、側移、抬高、手腕俯仰／旋轉候選，不移動。`rotations_only: true` 可在棋盤已入鏡後略過不需要的平移 IK。工程操作者核對該張影像和完整路徑後，將候選、畫面與路徑雜湊綁定的確認送到 `views/execute`；它連續移動、停穩並嘗試保存棋盤。候選只可執行一次，逾期、相機重連、保持目標改變或停止時失效。D435 不參與確認或校準輸入。

取景端點接受 16 ticks（約 1.4°）內的差異，同時把該差異納入整段模型檢查；沒有修改其他操作的容差。校準使用每張影像當下的實測角度，不使用命令的理想終點。棋盤看不全時不加入校準，但已完成的移動紀錄仍保留。每輪第一個實測姿勢另存不可覆寫的 `motion-origin.json`，服務重啟不會把限制原點偷偷移到目前位置。

工程校準的整輪手端範圍為原始姿勢周圍 120 mm，逐軸仍限制 240 ticks；單段仍不得超過 180 ticks／80 mm。120 mm 規格封存在候選內容中，只有工程校準入口可啟用，預檢與執行時核對相同範圍；正式抓取補看仍維持 80 mm。這讓多角度校準不會在起點的誤差包絡耗盡補看預算後，連向回走的候選都消失。

### 依實際進度同步關節

先前連續路徑的目標主要隨經過時間前進，較慢的關節可能還沒跟上，下一批目標就已往前走。新增 phase governor 後，改依實測的共同進度推進，並按照每一軸距離上次寫入的時間限制目標速度。這項修正沒有擴大原先通過檢查的路徑容差包絡；關節持續卡住時仍會在有限時間內停止。

實機側移工作 `b3affe94d0a04259a0adc13d6b55c1d4` 已完成，含停穩與取像共 5.42 秒，最大端點差 11 ticks。紀錄為 50 次目標更新、48 次限速、0 次等待，整段沒有雲端推論呼叫。旁觀錄影的開始、中段與結束畫面可見手臂姿勢改變，圓筒與棋盤仍在原位；這是事後影像核對，**不是連續碰撞驗證**。

這次側移後的姿勢超出 16 張校準照片涵蓋的關節範圍，已停止並保持姿勢。不能將啟用時通過的校準狀態沿用到這個新姿勢，也沒有用下述圓筒表面估距執行抓取。

### 實拍後的校準修正

- 棋盤辨識在獨立 CPU 程序執行，啟動前關閉 OpenCL；macOS 原生 OpenCV 辨識崩潰不再終止馬達控制器。子程序失敗或逾時只讓這張照片不被收錄，不能重播已完成的動作。
- 先以最長邊 960 px 搜尋完整棋盤，再回原圖精修角點。實拍完整棋盤由約 7.8 秒降至 0.4 秒；原圖角點與原本搜尋結果 p95 差約 0.001 px。被爪遮住的照片約 0.7 秒回報缺角。
- 內參只以 training 照片在候選鏡頭模型中選擇，先排除會在畫面邊緣折疊、不能正確反投影的畸變模型，再以 BIC 比較適配與參數數量。獨立 holdout 不參與選模。數學上全幅可反投影不等於已實拍驗證所有邊角。
- CAD 安裝矩陣中的 `-0.0` 統一為 `0.0`，避免同一安裝位置因浮點表示不同，被錯誤視為不同校準版本。
- 執行前最後一张影像直接與最初審核影像比較，避免兩次各自容許的小變化累積。

## 可用的回退

基準 commit：`4dac38aec19909dcbd1c31677d09b9b72e584960`，tag：`pre-spatial-v2`。本機備份在 `.runtime/spatial-releases/pre-spatial-v2-4dac38a/`，包含 source archive、設定與校準檔雜湊；沒有拷貝密鑰，也不把暫態馬達狀態當成可恢復設定。

**首選是工程頁切回「舊版」**。它在保持停止且無持物的狀態下，設 `spatial_backend=legacy`、`motion_backend=legacy`；新版相機 profile 不會再進入舊版估距，舊校準檔保留供比較，不改 EEPROM、不發馬達指令、不清掉其他人的 Git 改動。

`shadow` 目前只保留工程檢查入口，正式估距與動作仍走 legacy；尚未接入自動雙路比較，不能把它當作已完成的線上 A/B 系統。`v2` 使用新座標與本機路徑；沒有有效校準就直接指向設定流程，避免無效繞看。

每次模式／候選切換先保存原始 `config/robot.json` 到 `.runtime/spatial-config-history/<id>.json`，再原子替換設定，清掉舊物件座標快取。服務的 job lock 序列化切換；檔案寫入前再檢查是否有外部修改。請勿同時以外部編輯器改設定，這不是跨程式檔案鎖。

若需要退整個程式版本：先停止並確認沒有夾爪保持交易，再對本次實作 commit 做 `git revert`，依既有單一控制器啟動流程重啟；保留 `.runtime` 的停止／PWM 恢復紀錄，不能把 baseline 的舊執行狀態覆蓋回來。不要用 `git reset --hard`。若有持物未釋放，不應重啟或切版本，先完成原有放下流程。

## 2026-09-29 實拍結果

使用者已用尺確認 100 mm 核對線。棋盤維持固定，工作階段 `82bb3963cb744acd91c267d9171013cc` 收錄 16 個不同的腕部視角，每張均有完整 54 角點、原始 JPEG 雜湊及停穩後的六軸讀值。包含兩軸轉腕、退後抬高，以及側移停止後的實測位置；沒有把目標角度代替實測位置。

12 張用於擬合，4 張保留驗證。僅以擬合照片選出單一徑向係數的 Brown 模型；原本較複雜模型雖在中央像素誤差較低，卻會在畫面邊緣折疊，未予啟用。16 張結果的 training RMS 約 0.355 px，保留視角位置一致性最大差約 1.96 mm、角度差 0.25°、重投影 p95 最大 4.87 px。全幅反投影往返誤差最大 0.09 px 是數學一致性檢查，不是影像邊緣的實拍精度保證。

另凍結前 12 張中只用 9 張擬合的簡化鏡頭解，再檢查後收集的 4 張，沒有重新擬合：位置差約 1.17–2.01 mm，重投影 p95 約 3.15–5.56 px。這次校準相對原 CAD 相機先驗有數公分安裝位置與約 6° 方向差；因此先前未校準的距離不應繼續用於抓取。

已經 API 求解並套用持久化校準 `config/calibration/82bb3963cb744acd91c267d9171013cc-a58f1f0947f345e588a63e0b014b2d5f-profile.json`。服務重啟、相機世代更新後，以新的停穩實拍影像建立 observation packet，`metric_calibrated=true`、`jaw_calibrated=false`；記錄在 `.runtime/spatial-v2/board-placement/activated-spatial-state.json`。這確認校準綁定裝置、安裝與模型版本，可跨相機連線使用，並仍逐張檢查當前實測姿勢是否在採樣範圍內。

上述數字表示已採樣區域內固定棋盤的一致性，**不等於全工作空間的絕對定位或抓取精度**。肩部與手肘採樣範圍仍有限；兩側內夾墊與 TCP 尚待實測。D435 灰階旁觀錄影留在 `.runtime/spatial-v2/board-placement/observer-*`，只供事後核對手臂姿勢、棋盤與圓筒是否移動，沒有進入校準或路徑計算。

### 圓筒可見表面的離線重播

使用已保存的腕部照片與實測馬達角度，經正常校準封包、`active_depth` 與 `object_geometry` 流程重播。在第 16 張原圖內由工程操作者框選圓筒文字表面小區域 `[405, 682, 80, 60]`（原圖像素 x、y、寬、高），沒有將桌面、夾爪或整支圓筒的外框當成目標。未使用使用者提供的物件尺寸，也未使用 D435。

8 張照片約 1.7 秒得到 12 個表面特徵，其中 5 個跨至少 3 個視角；重投影 p95 約 2.77 px。可見文字表面沿相機光軸距離約 20.9 cm、相機至表面的直線距離約 23.3 cm。另兩組除最後參考影像外互不重複的視角子集估出約 20.2 cm 與 21.0 cm；這是重播一致性比較，不是獨立實測真值。

有效特徵的中位平移基線僅 11.76 mm，現有誤差敏感度公式給出的光軸距離範圍仍寬，約 12.4–29.4 cm。約 ±84.8 mm 的各項來源為：平移模型 34.8 mm、影像殘差 27.9 mm、旋轉模型 21.5 mm、焦距 0.6 mm；沒有為了縮小數字而修改參數。完整來源、影像雜湊、工程框、校準快照及公式拆解保存在 `.runtime/spatial-v2/board-placement/cylinder-replay.json`。**這只表示已估到可見表面，不代表完整尺寸、圓筒中心、雙指接觸位置或可執行的抓取。**

自動測試涵蓋尺度／座標、畸變、幾何擬合退化、保留照片驗證、不可混用舊 frame 或校準、接觸後新 TCP 路徑、模式切換與回退。最終測試數字以該次執行紀錄為準；不能代替上述實機驗收。

先前已於實際本機控制器演練 `v2 → legacy → v2`，三次切換前後關節狀態完全相同，保持停止且無 PWM 持物 owner；回滾備份與 6 個複製檔案的 SHA256 全數一致。本輪完整後端測試 1,310 項、略過 7 項，其餘通過；後續控制修正 91 項、相機校準與契約 49 項、模式切換與設定發布 API 16 項相關回歸通過。前端共 107 項測試通過（含新增 3 項校準頁舊結果顯示／套用阻擋測試），build、TypeScript 型別檢查與 lint 均通過。已啟用的是上述真實棋盤資料的校準，沒有啟用合成校準，也沒有宣稱新版實機抓取成功。
